# Dapper Dan database tool

This public, product-neutral tool owns two build-time artifacts:

- `src/DapperDan/Data/CompiledModels/*.cs`, generated by the pinned EF Core tool; and
- `src/DapperDan/Resources/Raw/dapper-dan-seed-v1.db3`, a deterministic SQLite schema and neutral Kai sample.

The iOS app never runs `EnsureCreated`, migrations, or another design-time `DbContext` operation. Those operations remain here in the ordinary JIT-capable build tool, then the app copies and validates the packaged seed on first launch.

Regenerate both artifacts after changing the entities or `DapperDanDbContext`:

```powershell
.\tools\DapperDan.DatabaseTool\Generate.ps1
```

An explicitly selected `dotnet` host can be supplied without changing the repository pin:

```powershell
.\tools\DapperDan.DatabaseTool\Generate.ps1 `
    -DotNetPath $env:PINNED_DOTNET
```

Review and commit every generated difference. The seed contains only fixed public canary data.

Generation is failure-safe: compiled-model source is completed and validated in a unique sibling
directory before the generated-only target directory is swapped, and the SQLite seed is completed
in a unique same-directory file before an atomic replacement. A failed generation therefore leaves
the last reviewed artifacts available.

EF emits a new `RuntimeModel` `modelId` on every optimization run even when the model is unchanged.
`Generate.ps1` requires exactly one such identifier and canonicalizes it to
`4d9c20ea-da25-4127-bf04-b92a9cd5ad8a` before installation. This GUID is only the stable identity of
the reviewed generated artifact; database compatibility remains governed by
`DapperDanDatabaseMetadata.SchemaVersion`.
